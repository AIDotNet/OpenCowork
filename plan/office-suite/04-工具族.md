# 04 · 工具族：让 Agent 真正会用文档

> 现状：Agent **读不了任何 Office 文件**（`FileTools.cs:49` 显式封禁 Read，`:57` 封禁 Grep），
> 只能靠 Python skill 在应用外操作，UI 全程不知情。
> 目标：Agent 和 UI 走**同一条 op 协议**，因此"Agent 改文档"天然就是"实时编辑更新"。

---

## 1. 工具清单

全部工具最终都落到 `doc/apply` / `doc/snapshot`，**不新开数据通路**。

### 读

| 工具             | 入参                       | 说明                                                                                                                                   |
| ---------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `DocumentOpen`   | `path`                     | 返回 `docId` + 结构概览：工作表名与维度、命名区域 / docx 大纲 / pptx 幻灯片列表。**不 dump 内容**，几百 token 让模型先知道文档长什么样 |
| `DocumentRead`   | `docId, selector, format?` | 范围读取。`Sheet1!A1:D50` / `outline` / `slide:3` / `paragraphs:10-40`。默认输出带类型标注的表格（区分数字、日期、**公式与其结果**）   |
| `DocumentSearch` | `docId, query, scope?`     | 跨工作表 / 段落 / 幻灯片定位，返回精确坐标。**这是当前 Grep 完全做不到的能力**                                                         |
| `DocumentRender` | `docId, target, index`     | 输出保真图像给多模态模型看。**这是"跟微软一样"的验证闭环** —— Agent 改完能自己看排版对不对                                             |

### 写（一律 `requiresApproval: true`）

| 工具             | 入参                    | 说明                                           |
| ---------------- | ----------------------- | ---------------------------------------------- |
| `DocumentEdit`   | `docId, ops[]`          | 批量结构化编辑，op 即 02 文档 §4.2 那套        |
| `DocumentSave`   | `docId, saveAs?`        | 显式落盘；原子写                               |
| `DocumentCreate` | `kind, path, template?` | 新建，可从 `resources/templates/` 或用户模板起 |

`DocumentEdit` 保持单一入口而不是拆成 `SheetSetCell`/`SheetInsertRow`/… 十几个工具：
工具表越长，模型选错的概率越高，且 `ops[]` 天然支持"一次调用改 200 个单元格"，
比循环调用省一个数量级的 token 和往返。

### 解封现有工具

| 改动                                                                                                                                                      | 位置                          |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `Read` 遇到 Office 文件不再拒绝，返回**结构化文本投影**（sheet → 带表头的 TSV；docx → 大纲 + 正文；pptx → 逐页文本）+ 一行提示"要编辑请用 `DocumentOpen`" | `FileTools.cs:46-51`          |
| `Grep` 搜同一份投影，不再跳过                                                                                                                             | `FileTools.cs:53-58`          |
| 附件栏的 Office 文件能被读进 prompt（用投影，不是原始字节）                                                                                               | `use-chat-actions.ts:538-575` |

**投影必须缓存**（按 path+mtime+hash），否则每次 Grep 都重解析一遍工作簿。

## 2. 注册路径：避开"写三遍"

现状（见 01 文档 §6）：渲染层 schema + worker executor + cron 分叉 schema = 最多三份。

**照抄 `codegraph-tool.ts:165-202` 那套**，那是全仓库唯一数据驱动的工具面：

```
worker 暴露 document/tools-list
  → 渲染层 refreshDocumentTools() 拉取并合成 handler
  → 走 dynamic-tool-catalog.ts 的 Phase B（每次请求前刷新）
```

这样**新增一种格式完全不用碰渲染层**。

cron 那份分叉（`cron-agent-background.ts:58,78,1157`）单独处理：
让 `buildAllowedToolDefinitions` 也从 worker 拉列表，
而不是继续往 `BACKGROUND_TOOL_DEFINITIONS` 里抄第三遍。
不做这一步的话，Document 工具在定时任务里会被 `:1311` **静默过滤掉且不报错**。

还要动的两处：

- `lib/chat-mode-tools.ts` —— 决定 chat 模式是否放行（建议：只放行读类）
- `AssistantMessage.tsx:2356` `renderToolBlock` —— 加一个 `DocumentToolCard` 分支

## 3. 结果卡片：`DocumentToolCard`

不要把整张表 dump 进聊天流。卡片应该显示：

- **改了什么**：`Sheet1!B2:B79 ← 79 个单元格`，公式变更单独列出
- **迷你 diff**：前 5 处改动的"旧 → 新"，其余折叠
- **一键定位**：点击 → `openFilePreview` 并**滚动到该区域高亮**
- **撤销**：一个按钮回滚这次工具调用的 op 批次（会话保有 op 历史，天然可逆）

最后一条尤其重要：Agent 批量改表最大的心理障碍是"改错了怎么办"。
op 批次级撤销把它变成可逆操作，用户才敢授权。

## 4. UI 驱动通道

工具要"定位到某个单元格并高亮"，必须往
`renderer-tool-bridge.ts:31-38` 那个**硬编码 6 项白名单**加方法。

不要为每个功能加一项（现在已经是 `ask-user` / `plan` / `team` / `subagent` /
`browser` / `canvas` 六个平行方法了，再加就是第七第八个特例）。
加**一个**通用文档方法：

```ts
| 'doc/ui-request'
// payload: { docId, action: 'focus'|'reveal'|'highlight'|'openTab', target }
```

由 `DocumentClient` 按 `docId` 路由到对应的 `DocumentHost` 实例。
后续 Word/Slide 的定位需求复用同一个方法，不再增白名单项。

## 5. Skills 与工具的分工

`resources/skills/{xlsx,docx,pdf,excel-processor,csv-pipeline}` **保留，不废弃**。

|                   | 用途                                                              |
| ----------------- | ----------------------------------------------------------------- |
| **Document 工具** | 交互式、增量、UI 可见、可撤销。日常编辑走这条                     |
| **Python skills** | 批处理、复杂数据分析、pandas 管道、格式转换。跑在文件层，不开会话 |

关键约束：**两条路径不能同时持有同一个文档的写权限**。
skill 通过 `Bash` 改了文件 → `FileGuard` 检测到 mtime 变化 → 推 `doc/external-change`。
若会话有脏数据，UI 弹冲突选择。skill 的 SKILL.md 里应加一句：
操作前若该文件已在编辑中，先 `DocumentSave` 或提示用户。

## 6. 提示词层面

`DocumentOpen` 的返回值本身就是给模型的"文档地图"，应包含：
工作表清单与维度、表头行推测、命名区域、**已存在的公式模式**
（例如"C 列 2:79 行统一是 `=A*B`"）、数据验证规则。

模型看到"C 列有统一公式"才不会在插入行时把公式写坏 ——
这类结构提示比多给几千 token 的原始数据有用得多。
