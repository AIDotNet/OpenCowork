# 02 · 架构设计：文档会话服务（Document Session Service）

> 单一核心判断：
> **文档必须从"一个字符串"变成"一个有版本的会话"。**
> 只要这一步做对，"用哪个渲染引擎"就退化成可替换的实现细节；
> 不做这一步，换任何引擎都会重蹈"保存即毁档"。

---

## 1. 先说清楚"跟微软完全一样"能做到什么程度

这是必须诚实对齐的前提，否则后面的选型全是空谈。

| 格式              | 纯前端能到的上限                                                                                               | 判断            |
| ----------------- | -------------------------------------------------------------------------------------------------------------- | --------------- |
| **Sheet（xlsx）** | **实用等价**：样式/合并/冻结/条件格式/数据验证/公式/图表都能自绘到"用户分不出来"                               | ✅ 可以达成目标 |
| **Slide（pptx）** | **很接近**：幻灯片是绝对定位的形状树，SVG 渲染 + 母版/主题继承可以做到高度还原                                 | ✅ 可以达成目标 |
| **Word（docx）**  | **做不到**。分页、页眉页脚、文字环绕、编号续接、域、目录、字体度量替换 —— 这是排版引擎级问题，不是渲染器能补的 | ❌ 需要真引擎   |

因此 docx 采用**双模解耦**，这是唯一诚实的方案：

- **保真只读模式**：worker 侧调 LibreOffice headless 转 PDF/SVG，用现有 `react-pdf` 显示
  —— 真正的所见即所得，跟 Word 排版一致。
- **结构化编辑模式**：段落 / 样式 / 表格 / 查找替换 / 批注，非分页 WYSIWYG。
  编辑提交后重新出保真渲染。

把"看得准"和"改得动"拆成两个模式，比做一个两头都不到位的 WYSIWYG 强得多。

LibreOffice **不打包进安装器**（体积 + LGPLv3 合规成本），做成
**按需下载的"保真渲染引擎"插件**，同时探测系统已装的 `soffice`。
默认包体不变；用户要"跟微软一样"就装引擎。这正好落在用户说的"作为内置插件"上。

## 2. 分层架构

```
┌──────────────────────── Renderer ────────────────────────┐
│  PreviewPanel（保留：Tab / 面包屑 / 工具栏）              │
│    └ DocumentHost                    ← 新增，替换 viewer 槽│
│        ├ NativeEngineFrame           Tier-1：ES module 直挂 │
│        │    ├ SheetEngine  (canvas 网格)                   │
│        │    ├ SlideEngine  (SVG 形状树)                    │
│        │    └ WordEngine   (保真页 + 结构编辑器 双模)      │
│        └ SandboxEngineFrame          Tier-2：iframe + postMessage│
│                                                            │
│  DocumentClient（会话客户端：revision / 乐观应用 / 重放）   │
└───────────────▲────────────────────────────────────────────┘
                │  doc:*  MessagePack IPC（二进制安全）
┌───────────────┴──── Main（薄代理，零文档逻辑）─────────────┐
│  document-handlers.ts → nativeDocumentRequest()            │
│  + doc/changed 流广播到所有窗口（含 DetachedSessionPage）  │
└───────────────▲────────────────────────────────────────────┘
                │  worker RPC
┌───────────────┴──── Native Worker (C#) ────────────────────┐
│  DocumentModule                                            │
│   ├ DocumentSessionStore   docId → 会话（内存中的解析包）   │
│   ├ OoxmlPackage           ZIP 部件级读写，未知部件原样保留 │
│   ├ FormatAdapter          sheet / word / slide            │
│   ├ PatchEngine            op[] → 部件级 XML 变更           │
│   ├ FormulaEngine          重算（可选，或委托 LibreOffice）  │
│   ├ RenderService          保真渲染（LibreOffice 引擎插件） │
│   └ FileGuard              mtime+hash 冲突检测 / 原子写入   │
└────────────────────────────────────────────────────────────┘
```

**为什么解析放在 C# worker：**
它已经是独立进程（崩溃不拖垮 UI）、已经是文件工具的所有者（权限模型统一）、
不可信文件的解析攻击面被进程边界挡住。渲染层只拿到已结构化的视图模型，
永远不碰原始 ZIP。

## 3. 关键机制一：部件级保留（Part-Preserving）

这是根治"保存毁档"的机制，也是整个设计的地基。

OOXML 是一个 ZIP：`xl/workbook.xml`、`xl/worksheets/sheet1.xml`、`xl/styles.xml`、
`xl/charts/*`、`xl/pivotCache/*`、`word/document.xml`、`ppt/slides/*`、
`customXml/*`、`vbaProject.bin` …

```
OoxmlPackage:
  载入：ZIP → Dictionary<partUri, byte[]>，只对需要的部件做 XML 解析
  编辑：只重写被 op 触及的部件
  保存：原封不动地回写所有未触及的部件
```

**不变式（必须写进单测）：**

> 打开一份文档，不做任何编辑，保存 —— 输出的 ZIP 与输入**逐部件字节相等**
> （除 `docProps/app.xml` 的时间戳外）。

有了这条不变式，图表、透视表、VBA、数据验证、条件格式、嵌入对象
**即使我们的适配器完全不理解它们，也不会被破坏**。
这是"支持所有 Excel 特性"的唯一可行路径 —— 不是全部实现，而是全部不动。

对应地，`xlsx` 那种 `book_new()` + `aoa_to_sheet` 的"重建式保存"必须彻底禁止。

### 3.1 AOT 风险（必须先做 spike）

worker 是 NativeAOT 发布的。`DocumentFormat.OpenXml` 反射/XML 序列化很重，
**AOT 兼容性未知，且本仓库已有 AOT 下异常消息退化为资源键的先例**。

- **首选**：手写 `System.IO.Compression` + `System.Xml.XmlReader/XmlWriter` 做部件级操作。
  `FileDocumentTools.cs:53-122` 已经在用这个路数读 docx 文本，成本可控，
  而且**部件级保留的设计天生只需要动少数几个部件**，不需要完整对象模型。
- **备选**：`DocumentFormat.OpenXml` + `TrimmerRootDescriptor`，需先验证 AOT 通过。

**M1 的第一个任务就是这个 spike**，结论决定后续两周的实现形态。

## 4. 关键机制二：会话协议 `doc/*`

### 4.1 生命周期 RPC

| 方法            | 入参                               | 出参                                            |
| --------------- | ---------------------------------- | ----------------------------------------------- |
| `doc/open`      | `{ path, sshConnectionId?, mode }` | `{ docId, kind, revision, meta, capabilities }` |
| `doc/close`     | `{ docId }`                        | —                                               |
| `doc/snapshot`  | `{ docId, scope }`                 | 视图模型（见 §5）                               |
| `doc/apply`     | `{ docId, baseRevision, ops[] }`   | `{ revision, effects[] }`                       |
| `doc/save`      | `{ docId, saveAs? }`               | `{ revision, mtime, hash }`                     |
| `doc/render`    | `{ docId, target, index, dpi }`    | `{ mime, data }` 保真图像                       |
| `doc/subscribe` | `{ docId }`                        | 流：`doc/changed`                               |

`capabilities` 让 UI 按引擎能力自适应，例如
`["read","edit","save","formula","style","render","comment"]`。
CSV 引擎只报 `read/edit/save`，Word 保真引擎报 `read/render` 不报 `edit`。

### 4.2 编辑操作（op）—— 统一信封，格式特化

```ts
type DocOp =
  // sheet
  | { op: 'setCell'; sheet: string; r: number; c: number; v?: CellValue; f?: string; s?: StyleId }
  | { op: 'setRange'; sheet: string; ref: string; rows: CellValue[][] }
  | { op: 'insertRows' | 'deleteRows'; sheet: string; at: number; count: number }
  | { op: 'insertCols' | 'deleteCols'; sheet: string; at: number; count: number }
  | { op: 'setStyle'; sheet: string; ref: string; style: StylePatch }
  | { op: 'merge' | 'unmerge'; sheet: string; ref: string }
  | { op: 'setColWidth' | 'setRowHeight'; sheet: string; index: number; size: number }
  | { op: 'addSheet' | 'removeSheet' | 'renameSheet'; sheet: string; to?: string }
  | { op: 'setValidation'; sheet: string; ref: string; rule: ValidationRule }
  // word
  | { op: 'insertText'; at: DocPosition; text: string }
  | { op: 'deleteRange'; range: DocRange }
  | { op: 'setParagraphStyle'; range: DocRange; style: ParagraphStyle }
  | { op: 'setRunProps'; range: DocRange; props: RunProps }
  | { op: 'replaceAll'; find: string; replace: string; options?: FindOptions }
  // slide
  | { op: 'setShapeText'; slide: number; shapeId: string; text: RichText }
  | { op: 'moveShape' | 'resizeShape'; slide: number; shapeId: string; box: Box }
  | { op: 'addSlide' | 'deleteSlide' | 'reorderSlide'; slide: number; to?: number }
  | { op: 'setNotes'; slide: number; text: string }
```

**这一条是整个设计的收敛点：UI 编辑和 Agent 工具产出的是同一种 op。**
一个协议，两个生产者 —— "实时编辑更新"和"tool 多功能支持"因此不是两件事，
而是同一件事的两个入口。

### 4.3 版本与冲突

每个 doc 持有单调递增 `revision`。`doc/apply` 必须带 `baseRevision`：

- `baseRevision == current` → 直接应用，`revision++`
- `baseRevision < current` → worker 侧 rebase（op 携带足够信息做位置变换），
  rebase 失败则返回 `{ conflict: true, effects }`，客户端用 `effects` 重放
- 客户端**乐观应用**本地 op 后立刻绘制，收到 `doc/changed` 时按 revision 对齐

这一套同时覆盖三种并发：**用户 vs Agent**、**主窗口 vs 分离窗口**、**多标签页**。

### 4.4 外部变更

`FileGuard` 监听 mtime+hash。文件被 Excel 或 Agent 的 `Bash` 改了：

- 会话无脏数据 → 静默重载，推 `doc/changed`
- 会话有脏数据 → 推 `doc/external-change`，UI 给"保留我的 / 用磁盘的 / 另存为"

**注意**：现有 `use-file-watcher.ts:52-120` 的做法是 bump `fileVersion`
让查看器**整份重读**。对会话式文档这会抹掉正在编辑的内容 ——
`DocumentHost` 必须退出 `fileVersion` 机制，改订 `doc/external-change`。

### 4.5 保存

- 永远"写临时文件 → fsync → 原子 rename"，替换现有的原地写
  （`fs-handlers.ts:817` 中途崩溃即损坏文档）
- 首次保存前对原文件做一次 `.bak`（可配置），
  在部件级保留的不变式被单测覆盖前，这是必要的安全网

## 5. 视图模型：分片 + 样式驻留

当前 `<table>` 一次渲染全部行。会话协议必须自带虚拟化语义。

**Sheet snapshot（按视口请求）：**

```ts
{
  docId, revision,
  sheets: [{ name, id, dimensions: { rows, cols }, hidden }],
  active: string,
  viewport: { r0, c0, r1, c1 },
  cells: Array<{ r, c, v, f?, t, s }>,   // s = 样式表下标，不内联样式对象
  styles: StyleTable,                     // 样式驻留：整表共享，去重
  merges, colWidths, rowHeights, frozen,
  validations, conditionalFormats,
  overlays: [{ kind: 'chart'|'image', anchor, renderRef }]
}
```

- **样式驻留**：单元格只带 `s: number`。10 万单元格 20 种样式 → 传 20 个样式对象。
- **overlays**：图表/图片不在前端重画，用 `doc/render` 出图贴在锚点上。
  保真且零实现成本，也不违反部件级保留。
- Word 按段落区间开窗，Slide 按幻灯片索引拉形状树。

## 6. 实时编辑的三条数据流

| 方向           | 路径                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| **UI 编辑**    | 网格 → 乐观应用 → `doc/apply` → worker → `doc/changed` → 其他窗口重绘         |
| **Agent 编辑** | 工具 → worker 内部直接 apply → `doc/changed` → **UI 在 Agent 干活时实时跳动** |
| **外部改动**   | FileGuard → `doc/external-change` → UI 询问                                   |

第二条是这次设计的门面特性：Agent 说"把 B 列求和填到 B80"，
用户**看着单元格变**，而不是等一个"文件已修改，是否重载"。

跨窗口广播走 main：worker 的 `doc/changed` 帧由
`document-handlers.ts` 扇出到所有 BrowserWindow，
分离窗口（`DetachedSessionPage`）因此自动同步。

## 7. 引擎选型

| 引擎          | 方案                                             | 依据                                                                                                                                                                                                                                                                                           |
| ------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Sheet**     | **自研 canvas 网格**（首选）或 Univer Sheets     | Univer 核心是 Apache-2.0，但 **OOXML 导入导出在 `@univerjs-pro/exchange-client`（商业 + 需服务端）**。OSS 路径必须自己写 OOXML ↔ snapshot 适配器 —— 而适配器正是保真度的难点本身，引入 Univer 并不能省掉它，反而多一层模型映射和一个大依赖。既然适配器要自写，直接对接自研 canvas 网格更可控。 |
| **Slide**     | **自研 pptx → SVG 渲染器**                       | 形状树 + 母版/版式继承 + 主题色 + 文本框排版。工作量中等，还原度高。                                                                                                                                                                                                                           |
| **Word 保真** | **LibreOffice headless → PDF**，`react-pdf` 显示 | 唯一能做到"跟 Word 一样"的路。作为可选下载引擎，不进默认包体。                                                                                                                                                                                                                                 |
| **Word 编辑** | 结构化编辑器（段落/样式/表格/查找替换）          | 非分页 WYSIWYG，配合上面的保真预览。                                                                                                                                                                                                                                                           |
| **PDF**       | 沿用 `react-pdf`                                 | 现状可用，补多页连续滚动 + 文本选择 + 搜索。                                                                                                                                                                                                                                                   |
| **CSV/TSV**   | 复用 Sheet 引擎，适配器降级                      | 顺手修掉 `.tsv` 存成逗号、空行被吞。                                                                                                                                                                                                                                                           |

**替换 `xlsx@0.18.5`**：worker 侧自写部件级读写后，
渲染层不再需要任何 OOXML 库，直接移除该依赖（同时消除 high 级漏洞）。
过渡期若需 Node 侧解析，用 `exceljs`。
